# The permission matrix is a pure test and the wiring is an HTTP one

**Three roles across seven resources is one table-driven test, not twenty-one HTTP requests.** ADR-0010 established that `role.authorize()` is pure and synchronous, which makes the entire matrix a `test.each` over a literal table — no server, no database, milliseconds. Spending an HTTP round trip per cell would buy nothing the pure test does not already prove, and would make the suite slow enough to skip.

What HTTP is spent on instead is **wiring, organised by tier and failure shape rather than by resource**: no session, a session with no active organization, the right session with the wrong role, and a well-formed id belonging to another organization — which must answer not-found rather than forbidden, per ADR-0012. Five tests, each against one representative server function. The claim being tested is that the tiers are attached and behave as designed; that the matrix inside them is right is the previous paragraph's job.

Beneath both sits **one repository-level scoping test**: another organization's document is invisible to a call carrying this organization's branded id. It proves the `WHERE` clause exists rather than trusting ADR-0011's directory convention to have been followed.

**The most valuable assertion in the suite is a meta-test: every server function declares a middleware tier.** The regression this application will actually suffer is a new server function shipped without one — and no matrix test and no wiring test can catch that, because both only cover functions somebody remembered to cover. A meta-test fails on code nobody thought about, which is the only kind of code that ships unauthorized. Whether the middleware chain is introspectable at runtime is unknown at the time of writing; if it is not, a static check over `src/server/` source is an acceptable substitute. The idea survives, the mechanism is the implementer's call.

**ADR-0011's other half — the branded `OrganizationId` — is verified at compile time, not runtime.** A types file with `@ts-expect-error` on a repository call passed a bare string proves that a URL parameter cannot reach a repository, and `pnpm typecheck` already runs it. The oxlint import fence gets no test: `no-restricted-imports` is a few lines of configuration whose failure is loud, and the fixture file that would prove it works is a permanent, confusing lint error checked into the tree.
